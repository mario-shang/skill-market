# Homework Collector（作业收集）

从作业照片或口述文本中提取三科作业，经用户确认后生成 2 行 3 列汇总图片。

## 流程

```
照片/文本 ──提取──> 三科清单 ──用户确认──> 修正循环 ──> 出图
```

### 第 1 步：收集输入

两种来源，可混合：
- **照片/截图**：直接用视觉能力读取（多模态 agent 无需 OCR 中间层）。板书、打印纸、群聊截图均可。
- **纯文本**：用户直接发作业内容或口述转写。

文本与照片并存时合并处理。多个文件时逐个读取后合并。

### 第 2 步：提取三科作业

从原始文本中提取语文/英语/数学三科的作业条目。规则：

**科目标题识别**：
- 只认"独立成行"的科目标题：`语文`/`语文作业`/`英`/`数学`/`english` 等别名（含单字别名 `语`/`英`/`数`，手写板书常见）。
- 判定前剥掉行首 emoji/装饰字符（如 `📚数学作业`）和行尾冒号/句号。
- **整行匹配，不做子串匹配**：`1. 用math方法解题` 是内容行，不是新科目标题；子串匹配会把后续条目挂错科目。

**条目清洗**：
- 去掉编号前缀：`1.`、`2、`、`①②③`。
- 保留原文其余部分，不意译、不改写。

**显式空标记**：
- 某科内容整条为 `<空>`（如"数学：<空>"）→ 该科为显式无作业，**有效**。
- 含 `<空>` 的其他文字（如"今天的<空>，明天补"）→ 保留原文，不误删。

**判定有效性**：三科各有 ≥1 条真实条目，或显式 `<空>` → 三科齐全，进入确认。缺科或存疑 → 把已有结果 + 缺失说明一起给用户（第 3 步）。

### 第 3 步：确认（必经，不可跳过）

**凡来源含照片/文件，必须确认后再出图**——视觉读取可能漏行、错字（手写体尤甚）。仅当用户直接发纯文本且三科齐全无歧义时可省确认。

生成确认文本（也可用脚本打）：
```bash
python3 ~/.claude/skills/homework-collector/scripts/render_homework.py \
  --chinese "听写第5课\n预习课文8" --english "抄写单词unit3" --math "口算第12页" --confirm
```

格式：
```
【语文作业】
  1. ...
【英语作业】
  1. ...
【数学作业】
  1. ...

请确认以上内容是否正确：
- 内容正确：回复【确认】生成图片
- 有错误：请直接说明问题，或提供完整的修正内容
```

### 第 4 步：处理修正意见

用户回复后分流（严格判定，防误覆盖）：

- **完整重提**：仅当回复里 **三科标题齐全且每科都有非空内容** 才整体替换。用户修正一科时常顺手抄另一科对照（"语文改成A，英语保持不变"）——非三科齐全一律不做整体替换，防止对照文本被误当重提而清空另一科。
- **局部修正**：按语义改对应科目条目；"没有作业/无/空" → 该科清空；"没问题/确认" → 不变。
- 不确定具体改动时，把理解后的新清单再走一遍第 3 步确认，不要猜。

### 第 5 步：生成汇总图片

```bash
python3 ~/.claude/skills/homework-collector/scripts/render_homework.py \
  --chinese "条目1\n条目2" --english "条目1" --math "条目1" \
  --output ~/homework/$(date +%Y-%m-%d).png
```

输出：A4 竖版，2 行 3 列表格（标题行 18pt 加粗居中 + 内容行 14pt `□ 条目`，文泉驿字体），200dpi PNG。转换失败时自动保留 .docx 到输出路径供人工排版。

依赖与解释器选择：脚本需 python-docx。依次探测解释器：当前目录/项目的 venv（`.venv/bin/python -c "import docx"` 探测）→ 系统 `python3`；都缺则 `pip install python-docx`。另需 libreoffice、pdftoppm、文泉驿字体（`fc-list | grep -i wqy` 自检）。

## 注意

- 不要替用户判定"这科应该没有作业"——缺科时如实说"没看到 X 科作业"。
- 修正循环没有次数上限，但每轮修完必须重新确认后才出图。
- 脚本只做排版出图，**不做内容提取**——提取、确认、修正全在对话里完成。
